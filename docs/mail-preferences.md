# Image and Undo send preferences

Open **Settings › Security**. These are real switches, saved privately for the signed-in user across devices. Defaults remain on for existing and new users. Changing one preference preserves the others; saving failures keep the previous state and show an error. Other open Settings tabs refresh through the existing accounts SSE topic with polling recovery.

| Preference                            | On                                                                                                       | Off                                                                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Load images through the privacy proxy | Allowed remote images use Spindle's bounded, public-address-pinned proxy/cache.                          | Allowed remote HTTPS images load directly in the browser. Image hosts can see the reader's IP and may track opens; browser cookie policies apply. |
| Block remote images by default        | New messages and formatted previews start with images blocked; **Display images** opts in for that view. | Images load automatically when opening formatted mail or a forwarded/provider original preview.                                                   |
| Undo send                             | New immediate send intents and safe explicit retries get five seconds before dispatch eligibility.       | New immediate sends and safe explicit retries become eligible as soon as their immutable MIME is ready.                                           |

Image policy defaults apply when opening/reopening a message or preview. **Hide images** overrides automatic loading for the current view; **Display images** overrides default blocking. Turning the proxy off does not itself consent to image loading: the blocking preference and per-view choice still apply. Plain-text views do not load images. Outgoing forwarded MIME keeps its existing recipient-controlled remote image URLs; preview preferences do not fetch images when sending or rewrite the saved original.

Direct loading preserves sanitized HTML/CSS, the separate content hostname, opaque sandbox, no scripts/forms/fonts/connect permissions, no-referrer policy and live owned grants. It allows only HTTPS image resources on validated public hosts, excludes app/content origins and private/reserved destinations, and adds only the approved image origins to that body's CSP. HTTP images and redirects to unapproved origins may fail in direct mode; re-enable proxying when needed. Inline CID images continue to use owned content endpoints. Direct browser requests cannot use the server's pinned DNS address, cache/byte limits or raster sniffing; the browser controls its own DNS/network/image handling. Session/content access is rechecked after DNS validation before returning a direct-image body. Existing displayed images cannot be recalled by changing a setting.

Undo send affects **future intents**, not already queued messages. Scheduled sends still honor their saved UTC deadline and database not-before guard, irrespective of this switch. Scheduling still requires a time at least five seconds ahead. Immutable content, attachment readiness/scanning, account/version/ownership checks, dispatch quotas, claim-versus-cancel ordering and unknown-delivery protections remain enforced. Cancellation is possible only before the worker claims a queued message; disabling Undo send provides no guaranteed cancellation window. Mail triage's separate five-second undo is unchanged.

## API, upgrade and rollback

`GET /api/mail/preferences` returns the current user's three booleans (`imageProxy`, `blockRemoteImages`, `undoSend`). `PATCH` accepts a nonempty partial object of exactly those boolean fields, with verified sessions, exact write origin, request limits and ownership derived from authentication. No user selector or admin override exists. A dedicated `mail_preferences` row cascades on user deletion; absence means all defaults on. Updates serialize with send enqueue through the existing user lock, so each frozen intent records one consistent grace deadline.

Deploy additive migration `0029_mail_preferences.sql`, then compatible API/content/worker and web code. Keep the table/trigger on rollback: older code ignores preferences and resumes its previous on/default behavior for new views/intents. Already queued intents retain their saved dispatch times, including any immediate intent made with Undo send off. No mail, draft, credential or immutable Outbox bytes are rewritten. No dependency, environment variable, provider connection or queue is added.
